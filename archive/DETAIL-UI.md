# 상세 기록 화면과 제목 관리

## 제목
`softm/softm.github.io`의 `projects/project-home.js`, `projects/projects.json`, `projects/chat-metadata.json`을 한 커밋에서 읽어 공개 목록과 상세 제목을 같은 함수로 계산한다. 사용자 지정 제목과 원래 채팅 제목의 우선순위를 그대로 따른다. 작성일은 촬영일·작업일·주문일·배포일로 추정하지 않는다.

`npm run build`의 준비 단계에서 archive/records.ts, 각 React 페이지의 h1, 기존 정적 HTML을 맞춘다. 날짜는 작은 별도 줄, 이름은 본제목으로 표시하되 전체 텍스트는 목록과 동일하다. 기존 채팅 URL은 바꾸지 않는다.

## 화면
큰 홍보용 배너 대신 짧은 기록 헤더를 사용한다. 본문 제목은 24–32px, 구역 제목은 21px, 구역 간 여백은 20–24px이다. 고정 높이와 빈 칸이 남는 고정 열 수는 쓰지 않는다. 사진은 화면 폭에 따라 4/2열 격자로 표시하고, 원본 비율을 보존하며 확대·이전/다음·키보드 조작을 제공한다. 안전상 주의는 접지 않고, 원본 링크·부가 안내는 참고자료에 모은다.

## 보존
상세 내용, 사진·영상·음성·PDF·ZIP 원본을 없애거나 새 요약으로 대체하지 않는다. 준비 단계 전후 바이너리 파일 해시가 다르면 빌드를 중단한다. 스타일은 상세페이지에만 적용하며 프로젝트 목록, 인증과 다른 앱 화면에는 적용하지 않는다.

## 검증
빌드 후 scripts/verify-detail-output.py가 모든 등록 상세 경로의 존재와 제목 일치를 검사한다. 운영 배포 후 Verify compact archive details 워크플로가 실제 브라우저로 제목, 사진 디코딩, 확대 보기, 1440/768/390/320px 화면 넘침을 검사하고 결과 JSON과 스크린샷을 보관한다. 현재 검증 대상은 화곡농장 공개 기록이며 다른 프로젝트에 자동 설치됐다는 의미는 아니다.
